# 推理開始時の再読み込み対策（2026-11-21）

基準：`f1a6a63`。iPhone でタイトルに戻る原因が実際に Safari のメモリ不足による再読み込みかは、まだ確定していない。今回の Mac 上の WebKit では修正前後とも同じ手順を完走し、ページのクラッシュは再現しなかった。

## 記録と復旧

推理開始直前に、通常の３枠とは別の自動記録を localStorage に保存し、時刻・部屋・問の番号・自動記録の識別子を sessionStorage に記録する。演出が終わって問１の操作が可能になれば印を消す。

次の起動時に印が残り、自動記録の識別子が一致すれば、タイトルを表示せず推理開始前の探索状態を復元し、画面の隅に「読み込み直しから再開しました」と表示する。推理を再開する操作はプレイヤーが行う。コンソールにも警告を出す。保存に失敗・記録が壊れた・別のタブによって自動記録が更新された場合は、誤った進行を復元せずタイトルを表示して、その旨を通知する。保存領域が使えない場合もゲームを止めない。通常の３枠は上書きしない。

## メモリ対策

- 大画面の filter のアニメーションを廃止。彩度を落とす合成レイヤーの opacity を変えて白黒と色の切り替えを表現し、揺れは transform で行う。動く立ち絵の通常時の CSS filter は推理中だけ外す。背景は既存の白黒版を使う。
- 画像のキャッシュは各人物の現在の表情・口と目の差分、および現在の部屋を中心に残す。推理中に白黒背景の用意ができたら、元のカラー背景の表示参照を外す。白黒背景を読み込めない場合は元の背景を再表示する。
- 時間帯の光は現在の部屋・時間の ImageBitmap だけを保持。古い ImageBitmap を close し、計算後の Worker を終了する。推理開始時にも光の保持分と処理を解放する。
- 口パク canvas は表示寸法×devicePixelRatio を上限とし、元画像以上にはしない。非表示の背景 canvas は推理中１×１に縮める。集中線は開始時だけ読み込み、終了時に表示参照を外す。素材ファイルは変更していない。

## WebKit の測定結果

Mac の Playwright WebKit、912×420、deviceScaleFactor 3、通常演出。キャッシュを持たない新規コンテキストで、冒頭から全手がかり、推理、問１〜５、エンディングまで自動操作した。画面撮影の負荷を混ぜずに `ps` の RSS を約0.5秒ごとに取得。WebContent はページプロセス、WebKit 合計は新たに起動した WebContent・GPU・Networking の RSS の和。MiB は 1,048,576 bytes。各１回の結果であり、RSS は共有メモリを含むため合計は実使用量と一致しない。

| 測定区間 | 修正前 WebContent | 修正後 WebContent | 修正前 WebKit 合計 | 修正後 WebKit 合計 |
|---|---:|---:|---:|---:|
| 推理開始演出中の最大 | 606.8 MiB | 610.7 MiB | 931.9 MiB | 926.9 MiB |
| 問１〜５の区間の最大 | 638.9 MiB | 633.4 MiB | 977.9 MiB | 984.3 MiB |

**推理開始時の最大 RSS はこの測定では下がっておらず、目標の大幅削減・半減は達成できていない。** 別の測定ではより低い値も出たが、実行間の変動があるため、最終実装と同じ条件の結果を上に記載する。Mac の WebKit の値は iPhone Safari のメモリ上限や動作を保証しない。[0.5秒ごとの表](memory-samples.csv)／[修正前の詳細](before-memory.json)／[修正後の詳細](after-memory.json)。

## iPhone 実機での確認

1. iPhone の「設定」→「Safari」→「詳細」で「Web インスペクタ」をオンにする。
2. Mac の Safari で「開発」メニューを有効にし、iPhone を接続して試作ページを開く。Mac の「開発」メニューから iPhone の該当ページを選ぶ。
3. Web インスペクタの「タイムライン」でメモリを記録し、最初から手がかりを集めて推理開始まで進む。開始前後の最大値と、画面が戻った時のログ・「読み込み直しから再開しました」の表示を確認する。

機種・iOS のバージョンや設定によってメニュー名や接続手順が異なる場合がある。警告が出ても、それだけで原因がメモリ不足と確定するわけではない。
