# スマートフォン横向きの配置修正（2026-11-20 指示）

## 修正内容

横向きの低い画面で、付せん・人物・捜査コマンド・調べる先の位置を変更していた上書きを削除。1280×720を基準に、912×356／912×420／844×390／667×375の各画面でも、舞台座標が次の値で一致することを確認した。

| 部品 | 舞台上の位置 |
|---|---|
| メニュー | 左1630・上6 |
| ハルキ | 左-12・上599、472×531 |
| サイジ | 左1475・上592、472×531 |
| 捜査コマンド | 左1462・上108 |
| 調べる先 | 左1722・上136 |

コマ、６つのコマンド行、会話の紙も1280×720と同じ舞台座標。探索中も立ち絵を消さない。狭い横画面の会話本文の下限は維持し、両方の話者で会話の紙と立ち絵に重ならないことを確認した。

項目数が多く一覧の末尾が舞台外になる場合に限り、**一覧の起点は動かさず**、項目間隔を詰め、長い項目の幅を広げる。必要な場合だけ項目の高さを調整する。実際の最大８項目では４サイズすべてで末尾まで表示・操作でき、最小のタップ領域は約37pxだった。従来テスト用の９項目では最小約34pxになるサイズがある。

横向きの拡大率と中心は `visualViewport` のサイズ・オフセットから計算し、`resize` と `scroll` に追従。左右の安全領域が異なるときは大きい方を両側に適用して中央を保ち、表示領域からはみ出さないようにした。縦向きの専用配置と計算は維持し、390×844の修正前後で主要部品の座標が一致することを確認した。

## 検証

- `tests/mobile-landscape-261120.cjs`：基準と４サイズの舞台座標、探索中の人物、両話者の本文、一覧、推理、表示領域のリサイズ・スクロール・オフセット、左右非対称の安全領域を検証。
- `tests/cmd-261120.cjs` と既存のシナリオ・手帳・セーブ・推理・立ち絵・効果音・レイアウトのテストを実行。既知の `tests/transfers.cjs` は以前から `showWindow is not defined` で失敗する別件で、実ブラウザの `scene-transfers.cjs` は合格。
- iOS Simulator：`xcode-select -p` は Command Line Tools を示し、`xcrun simctl` が見つからないため実行できなかった。iPhone Air実機・Safariでの確認は未実施。
- 追加の UI 自動監査（844×390・667×375、各35状態）：会話本文の切れ・文字の画面外はみ出し・ボタンの覆いは各0件。一方、手帳などの12px未満の文字94件、36px未満のボタン31件、同梱外フォントの使用3件が検出された。詳細は [監査結果](ui-audit-summary.txt)。これらも含めた監査は合格ではない。
- ９サイズ一括の追加 UI 監査は３サイズ完了後にブラウザが終了したため完走していない。別の `tests/ui-layout.cjs` は９サイズすべて合格。
