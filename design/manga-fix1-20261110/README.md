# 原稿用紙UI FIX1 修正報告

2026-11-10 / v0.16.0 / 作業前コミット：90fc867

## 直した内容

1. **推理の本文切れ**：推理時に会話を旧レイアウトへ戻していた処理を外し、探索と同じ原稿用紙の舞台に統一した。白い紙2枚、人物名画像、明朝本文、文末の赤い三角を使用する。推理5問とも全文を表示でき、Enterで文字送りの即時表示・次ページ送りも行える。問題枠は白紙と墨線、選択中は赤鉛筆の丸にした。第5問の選択欄も同じ丸を使う。推理背景画像と推理の処理内容は変更していない。
2. **廊下の調査先**：移動後に選択が空なのに「調べる」を強調し、古い紙片へ矢印を出していた不整合を修正した。移動直後はその場所の「調べる」を選び、廊下では掲示板・扉を表示する。ホバー・キー選択も選択状態と紙片一覧に同期する。未選択や対象がない状態では矢印を消し、矢印の座標は現在の文字と紙片の位置から求める。
3. **コマンドの重なり**：固定の行座標をやめ、拡大された切り抜き文字が行の高さを持つ縦配置へ変更した。6つの選択状態で、回転・変形後の文字の境界を計測した。1920×1080で隣接行の最小間隔は約6.4px。どの選択状態でも文字は重ならない。
4. **会話選択肢**：黒い四角の枠を外し、少し傾いた白い紙片と影に変更した。選択中は既存のtopic-circle.pngで示し、本文の実際の高さを測ってその下へ配置する。

## 検証

合格：conditions / story / menu-phs / presentation-resolution / assets / logic / saves / stability / scene-transfers / portrait-animation / menu-phs-browser / manga-rebuild / manga-fix1 / ui-layout / ui-audit。

- 9サイズで推理5問の全ページを描画し、原文と表示用ページを照合した。本文の欠落、極端に細い列、描画範囲のはみ出しはない。
- ui-auditは、inline要素のclientHeightだけに頼らず、本文の実際の描画範囲、本文欄の幅、内容の高さ、親要素による切れを検査するようにした。本文を100pxの列や10pxの高さにする故障テストが失敗することも確認した。
- 315状態（9サイズ×35状態）の監査に合格。文字切れ・細い列・画面外・小さい操作ボタン・隠れた操作・コントラスト・同梱外書体・JS/HTTPエラーは0件。PHS本体の装飾用ミニ表示は従来の除外を維持する。
- ホバーによる6コマンドの選択を9サイズでも追加測定し、問題がないことを確認した。
- 前回未解決の旧transfers.cjs（廃止済み保存持ち運びAPIの旧テスト）は今回も変更していない。

シナリオJS/JSON、assets以下の画像は変更していない。画像の生成・加工は行っていない。新しい推理デザインmanga-deduceは制作していない。
